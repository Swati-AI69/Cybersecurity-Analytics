# Cybersecurity Analytics — MySQL & Python EDA

##  Project Overview

Cybersecurity is not only about protecting systems — it is also about understanding what is happening inside those systems.

In this project, I analyzed cybersecurity-related data from different organizations to understand patterns in:

* User login activity
* Failed login attempts
* Network events
* System criticality
* Security incidents
* Organizations and industries
* Users and their roles
* Security activity over time

The project combines **MySQL for data storage and SQL-based analysis** with **Python for data cleaning, feature engineering, exploratory data analysis (EDA), statistical analysis, and visualization**.

The main goal was to take multiple related cybersecurity tables, connect them together, clean and validate the data, and turn the raw data into meaningful insights.

---

##  Project Objective

The main objectives of this project were to:

1. Store and organize cybersecurity data in a MySQL database.
2. Understand the structure and relationships between different tables.
3. Validate the quality of the data before analysis.
4. Combine information from multiple tables using joins.
5. Create useful organization-level metrics.
6. Explore login behavior and failed login activity.
7. Analyze network events and their severity.
8. Understand security incidents and their characteristics.
9. Identify unusual patterns and outliers.
10. Analyze how cybersecurity activity changes over time.
11. Use visualizations and statistical techniques to better understand the data.

## Dataset Structure

The project uses **7 related tables**.

| Table                | Description                                                         |
| -------------------- | ------------------------------------------------------------------- |
| `organizations`      | Contains information about organizations, industries, and countries |
| `systems`            | Contains systems belonging to each organization                     |
| `users`              | Contains users and their roles                                      |
| `login_logs`         | Contains user login activity and login status                       |
| `network_events`     | Contains events generated by different systems                      |
| `security_incidents` | Contains recorded cybersecurity incidents                           |
| `incident_systems`   | Connects security incidents with affected systems                   |

# 2️. Data Cleaning & Validation

Before performing EDA, I checked whether the data was reliable enough for analysis.

The following checks were performed:

### Missing Values

I checked every table for missing values.

**Result:** No missing values were found in the tables.

### Duplicate Records

I checked:

* Duplicate rows
* Duplicate primary keys
* Duplicate incident-system relationships

**Result:** No duplicate records or duplicate primary keys were found.

### Data Consistency

I checked categorical values for unnecessary whitespace and casing inconsistencies.

### Date Validation

The following columns were converted into proper datetime format:

* `login_time`
* `timestamp`
* `discovered_date`

This made time-based analysis easier.

### IP Address Validation

Login IP addresses were checked for:

* Incorrect formatting
* Invalid IP octets

**Result:** No malformed or invalid IP addresses were found.

### Referential Integrity

Because the project contains multiple related tables, I also checked whether foreign-key relationships were valid.

For example:

```text
Users → Organizations
Systems → Organizations
Login Logs → Users
Network Events → Systems
Security Incidents → Organizations
Incident Systems → Incidents
Incident Systems → Systems
```

**Result:** No orphan records were found.

### Cleaning Summary

The dataset was already structurally clean, so there was no need to remove or impute records.

The main transformation required for analysis was converting the relevant date columns into datetime format.

# 3️. Feature Engineering

The raw tables contain many IDs and categorical columns.

To perform deeper analysis, I combined information from multiple tables.

For example:

### Login Data

Login records were joined with:

```text
login_logs
      ↓
users
      ↓
organizations
```

This allowed login activity to be analyzed by:

* Organization
* Industry
* Country
* User role
* Login status

### Network Data

Network events were connected with:

```text
network_events
      ↓
systems
      ↓
organizations
```

This made it possible to analyze network activity together with system and organization information.

### Incident Data

Security incidents were connected with organization information.

Incident-system relationships were also combined with system and incident attributes.

# 6️. Outlier Analysis

Outlier analysis was performed on the organization-level numerical metrics.

Metrics such as:

* Number of systems
* Number of users
* Number of incidents
* Number of critical systems
* Failed login counts
* Incident rate

were examined to identify organizations with unusual values.

Outlier analysis is useful in cybersecurity because unusually high activity can sometimes deserve additional investigation.

However, an outlier does **not automatically mean that an organization has a security problem**. It simply indicates that the value is unusual compared with the rest of the dataset.

# Data & Security Note

The project connects to a local MySQL database.

Database credentials are stored locally using environment variables rather than being shared publicly.

For security reasons:

* Database passwords should never be committed to GitHub.
* `.env` files should remain private.
* Local datasets are excluded from the repository.

If you want to run this project on your own machine, you will need to create your own MySQL database and provide your own database credentials.

# How to Run the Project

## Step 1 — Clone the repository

```bash
git clone https://github.com/Swati-AI69/Cybersecurity-Analytics.git
```

Then move into the project folder:

```bash
cd Cybersecurity-Analytics
```

---

## Step 2 — Install Python libraries

Install the required libraries:

```bash
pip install pandas numpy matplotlib seaborn scipy mysql-connector-python python-dotenv jupyter
```

---

## Step 3 — Set up MySQL

Create the required database and tables in MySQL.

The project expects a database named:

```text
soc_analytics
```

The database should contain the 7 tables used in the notebook.

---

## Step 4 — Create your `.env` file

Create a `.env` file in the project folder.

Add your own MySQL connection details:

```text
DB_HOST=localhost
DB_USER=your_mysql_username
DB_PASSWORD=your_mysql_password
DB_NAME=soc_analytics
```

Do **not** upload this file to GitHub.

---

## Step 5 — Open the notebook

Open:

```text
Cybersecurity_py_sql.ipynb
```

using Jupyter Notebook or VS Code.

Run the cells from top to bottom.
